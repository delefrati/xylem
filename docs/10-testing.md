# 10 — Testing strategy

Git is the **oracle**. Wherever Xylem answers a question git can also answer, the parity suite compares them. This gives the implementing agent an objective, automatic definition of "correct".

## Test layers

| Layer | Scope | Command | Needs Docker |
|---|---|---|---|
| Unit | Pure packages: hash, object, changeset, treeops, diff, merge, revision, derived computations (with in-memory fakes) | `make test` | no |
| Fuzz | Encoders/decoders, diff, tree apply, jump pointers | `make fuzz` (30 s per target; longer in nightly CI) | no |
| Integration | `meta` against real Postgres, `store/s3` against MinIO, server end-to-end over in-process gRPC (`bufconn`) | `make test-integration` | yes |
| Parity | Import fixture repos and compare every query with git | `make parity` | yes |
| CLI e2e | Build binaries; run `xy` against a live `xylemd` in temp dirs | `make e2e` | yes |
| Race | All of the above with `-race` in CI | `make check` | yes |

Build tags: integration, parity and e2e tests use `//go:build integration`, `parity` and `e2e` respectively, so plain `go test ./...` stays fast and Docker-free.

## Golden vectors (`testdata/golden/`)

Hash-affecting encodings are pinned by golden files, created once in M1 and reviewed by a human:

- `blob_empty`, `blob_hello` → expected id.
- `tree_*.bin` → expected encoding bytes and id for small trees (every mode, sorting edge cases).
- `changeset_*.bin` → root, merge, deletes, extras, non-UTF-8 path.

The test fails if the encoding changes. Regenerating requires `UPDATE_GOLDEN=1` **and** an ADR entry.

## Property and fuzz tests (must exist)

- `object`: `Decode(Encode(x)) == x`; no single-byte mutation of a stored frame passes `Verify` with different content. (A few zstd header mutations, such as a larger window descriptor, decode to identical bytes and therefore still verify; integrity is about content, not frame bytes.)
- `treeops`: for random sequences of change lists, incremental `Apply` gives the same root id as building the full tree from scratch (brute force).
- `diff`: applying `diff(a, b)` to `a` yields `b`; the edit script is minimal on small random inputs (compare with a DP LCS for length ≤ 50).
- `derived/core`: jump-pointer `ancestorAtDepth` equals a naive walk on random trees, depth ≤ 10k.
- `merge-base`: equals a brute-force reachability-set computation on random DAGs ≤ 300 nodes.
- `merge` (M7): clean diff3 merges are symmetric with respect to non-overlapping edits.

## Database tests

`internal/testutil.NewDB(t)`:
1. Connects to `XYLEM_TEST_DB_URL` (default `postgres://xylem:xylem@localhost:54329/postgres?sslmode=disable`).
2. Ensures a template database named `xylem_tmpl_<first 12 hex of the hash of all migration files>` exists with migrations applied. It is created under `pg_advisory_lock` (because `go test ./...` runs package binaries in parallel), with create-if-missing semantics, and never dropped, so a new migration simply yields a new template name.
3. Per test, runs `CREATE DATABASE t_<random> TEMPLATE xylem_template` and drops it in `t.Cleanup`.

This takes milliseconds per test and gives full isolation, so tests can run with `t.Parallel()`.

Object store in tests: `store.NewMem()` for unit tests, `store.NewFS(t.TempDir())` for integration, and MinIO only for `store/s3` tests.

## Fixture repositories

### Synthetic (`scripts/make-fixture-repo.sh <dir> <profile>`)

Deterministic: fixed `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` incremented per commit, fixed names, and `git -c core.autocrlf=false`. Profiles:

| Profile | Contents |
|---|---|
| `tiny` | 10 commits, linear, adds, modifies, deletes |
| `edge` | Every edge case from `08-git-import.md` (merges incl. octopus, file↔symlink↔dir, exec flips, non-UTF-8 paths, empty commit, encoding header, submodule, large binary, duplicate blobs) |
| `branchy` | ~2,000 commits generated by a small Go program (`scripts/genrepo`): random feature branches merged back, random edits to ~300 files, so blame and merge-base get exercised |

Output goes under `testdata/fixtures/` (gitignored) and is generated by `make fixtures`.

### External (`scripts/fetch-external-fixtures.sh`)

Clones pinned commits of real repos into `testdata/external/` (gitignored), used by `make parity-external` (not in default CI):

- small: `github.com/spf13/cobra`
- medium: `github.com/prometheus/prometheus`

Pin exact commit shas in the script for reproducibility.

## Parity suite (`internal/parity`, `xylemd parity`)

Given a git repo and a Xylem server that imported it:

| Check | git side | Xylem side | Pass criteria |
|---|---|---|---|
| Tree | `git ls-tree -r -z --full-tree -l <sha>` | `ListDirectory(recursive)` | exact (path, mode, size), content via blob mapping |
| Log (repo) | `git log --first-parent --format=%H <tip>` | `Log(main)` | exact sequence |
| Log (path) | `git log --first-parent --format=%H <tip> -- <path>` | `Log(main, path)` | exact sequence; 50 sampled files and 10 sampled dirs |
| Diff (names) | `git diff --name-status --no-renames -z A B` | `Diff(A, B)` | exact set with statuses |
| Diff (content) | — | `Diff(A, B, hunks)` | applying hunks to A's file yields B's file (algorithm differences allowed) |
| Blame | `git blame --first-parent --porcelain <sha> -- <path>` | `Blame` | % lines with same origin; 100% on `tiny`/`edge`, ≥ 99% on `branchy` and external |
| Merge-base | `git merge-base --all A B` | `MergeBase` | exact set; 200 sampled pairs |
| Is-ancestor | `git merge-base --is-ancestor A B` | `IsAncestor` | exact; 500 sampled pairs |
| Read file | `git cat-file blob <sha>:<path>` | `ReadFile` | byte-identical; 200 samples |
| Clone (M5) | `git archive <sha> \| tar -x` | `xy clone` (full and sparse) | identical files, modes, symlink targets |

Submodule entries (mode 160000) are filtered out of every git-side output (`ls-tree`, `diff --name-status`, `archive` has none) because Xylem skips them by design.

Sampling uses a fixed seed (`--seed`, default 42) so failures are reproducible. The parity report is printed as a table and written as JSON to `parity-report.json`. **The parity suite is the acceptance gate for M3, M4 and M5.**

Why blame isn't 100% on real repos: Myers implementations can choose different but equally minimal alignments, which shifts attribution on ambiguous lines. Mismatches are listed so a human can review that they're only ambiguous-alignment cases.

## Benchmarks (`make bench`, informational)

- `BenchmarkTreeApply/{10,100,1000}files` against a 100k-file base tree.
- `BenchmarkCreateChangeset` (integration) → latency percentiles.
- `BenchmarkBlame` cold and warm on `branchy`.
- `xylemd import` throughput on the medium external repo (logged by the importer).

Record notable results in `docs/progress.md`.

## CI (GitHub Actions, `.github/workflows/ci.yml`)

- Jobs: `lint` (golangci-lint, `buf lint`, `buf breaking` against main after M4), `unit`, `integration` (service containers postgres:17 + minio), `parity` (synthetic fixtures), `e2e`.
- Everything runs with `-race`.
- A nightly job runs `make fuzz FUZZTIME=5m` and `make parity-external`.
